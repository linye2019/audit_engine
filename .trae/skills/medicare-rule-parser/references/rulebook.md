# 医保智能监管规则分类体系与检出逻辑归纳

## 一、规则大类体系

### 1.1 药品类规则

| 规则子类 | 检出逻辑模式 | 逻辑依据来源 | 典型批次 |
|----------|-------------|-------------|---------|
| 性别限定 | 与限定性别不符 | 药品说明书适应症 | 第一批-1 |
| 人群限定（儿童专用） | 参保人年龄超出儿童年龄限制 | 药品说明书适应症 | 第一批-3 |
| 人群限定（限儿童） | 参保人年龄超出儿童年龄限制 | 2024版国家药品目录备注 | 第一批-4 |
| 险种限定 | 参保人险种非X保险 | 限工伤保险/限生育保险 | 第三批 |
| 就医方式限定 | 使用药品的就医方式不符合限定就医方式 | 2024版国家药品目录备注 | 第四批 |
| 机构级别限定 | 使用药品的医疗机构级别低于限定级别 | 2024版国家药品目录备注 | 第五批 |
| 适应症限定 | 使用药品的疾病诊断不符合限定支付适应症 | 2025版国家药品目录备注 | 第十二~十七批 |
| 使用顺序限定 | 使用了该药品，但没有一线药品使用无效或不能耐受的证据 | 国家药品目录二线用药限制 | 第九批 |
| 疗程限定 | 使用药品的数量/天数超过限定支付疗程 | 国家药品目录疗程限制 | 第六批 |
| 渠道限定 | 药品不属于互联网医院支付范围 | 互联网诊疗管理办法 | 第十批 |
| 中药饮片支付限定 | 单独使用/单复方均使用时统筹基金不予支付 | 国家医保支付政策 | 第十一批 |

### 1.2 医疗服务项目类规则

| 规则子类 | 检出逻辑模式 | 逻辑依据来源 | 典型批次 |
|----------|-------------|-------------|---------|
| 性别限定 | 与限定性别不符 | 国家项目指南性别限制 | 第一批-2 |
| 人群限定（儿童专用） | 参保人年龄超出儿童年龄限制 | 儿童专用项目 | 第一批-5 |
| 频次限定 | 使用项目的数量总计超过上限数量 | 国家医保局项目计价单位 | 第八批-1/4 |
| 人群限定（限年龄） | 参保人年龄不符合限定条件 | 国家项目指南年龄限制 | 第八批-2 |
| 疗程限定 | 使用项目的数量/疗程超过限定支付疗程 | 国家项目指南疗程限制 | 第八批-3 |
| 重复收费 | 同一项目对在同一次就诊中同时收费，项目B已包含在项目A价格中 | 国家医保局项目A含项目B说明 | 第七批 |
| 折价收费 | 经同一切口进行的两种及以上手术，第二及以后未按规定折价 | 同切口组别名称 | 第二批 |

### 1.3 项目对类规则（第七批专用）

第七批重复收费规则的列结构为9列，与通用项目类不同：

| 列序 | 列名 | 说明 |
|------|------|------|
| 0 | 序号 | 知识点序号 |
| 1 | 时间区间 | 检测时间范围（单日/同次就诊等） |
| 2 | 医疗服务项目A名称 | 主项目名称 |
| 3 | 医疗服务项目A代码供参考 | 主项目代码（15位数字） |
| 4 | 医疗服务项目B名称 | 被包含项目名称 |
| 5 | 医疗服务项目B代码供参考 | 被包含项目代码（15位数字） |
| 6 | 检出逻辑 | "项目A和项目B同时收费" |
| 7 | 逻辑依据 | 说明项目A包含项目B的原因 |
| 8 | 备注 | 各省配置说明 |

## 二、检出逻辑标准化

### 2.1 药品类检出逻辑模板

```
性别限定:    与限定性别不符
儿童专用:    参保人年龄超出儿童年龄限制
险种限定:    参保人险种非{X}保险
就医方式:    使用药品的就医方式不符合限定就医方式
机构级别:    使用药品的医疗机构级别低于限定级别
适应症限定:  使用药品的疾病诊断不符合限定支付适应症
二线限定:    使用了该药品，但没有一线药品使用无效或不能耐受的证据
疗程限定:    使用药品的数量/天数超过限定支付疗程
渠道限定:    药品不属于互联网医院支付范围
饮片限定:    单独使用时统筹基金不予支付 / 单复方均不予支付
```

### 2.2 医疗服务项目类检出逻辑模板

```
性别限定:    与限定性别不符
儿童专用:    参保人年龄超出儿童年龄限制
频次限定:    使用项目的数量总计超过上限数量
超频次:      使用项目的数量在周期内超过上限数量
限年龄:      参保人年龄不符合{条件}
疗程限定:    使用项目的数量超过限定支付疗程
重复收费:    {项目A}与{项目B}同时收费，属于重复收费
折价收费:    经同一切口进行的两种及以上不同的手术，第二及以后的手术未按规定折价计收
```

## 四、规则条件 DSL 映射

### 4.1 药品-险种限定

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_line.med_list_code", "op": "in", "value": ["药品代码列表"]},
    {"field": "claim_event.insurance_type", "op": "!=", "value": "工伤"}
  ]
}
```

### 4.2 药品-适应症限定

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_line.med_list_code", "op": "in", "value": ["药品代码列表"]},
    {"field": "claim_event.diagnosis_codes", "op": "not_contains", "value": ["适应症ICD-10代码"]}
  ]
}
```

### 4.3 药品-二线使用限定

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_line.med_list_code", "op": "in", "value": ["二线药品代码"]},
    {"field": "claim_event.claim_lines", "op": "not_exists", "value": {"med_list_code": "in:一线药品代码"}}
  ]
}
```

### 4.4 医疗服务项目-频次限定

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_line.project_code", "op": "in", "value": ["项目代码列表"]},
    {"field": "claim_line.quantity", "op": "gt", "value": "daily_limit"}
  ]
}
```

### 4.5 医疗服务项目-重复收费

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_event.claim_lines", "op": "coexists_with", "value": {"project_code": "项目A代码"}},
    {"field": "claim_event.claim_lines", "op": "coexists_with", "value": {"project_code": "项目B代码"}}
  ]
}
```

### 4.6 医疗服务项目-折价收费

```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_event.same_incision_group_count", "op": "gt", "value": 1},
    {"field": "claim_line.is_discounted", "op": "eq", "value": false}
  ]
}
```

### 4.7 药品-性别限定

```json

  "logic": "AND",
  "conditions": [
    {"field": "claim_line.med_list_code", "op": "in", "value": ["药品代码列表"]},

  ]
```

## 五、数据导入注意事项

1. **合并单元格**：药品代码 Sheet 中"对应知识点序号"列存在合并单元格，需 `ffill()` 前向填充
2. **列头行偏移**：大部分文件列头在第4行（index=3），第二批手术折价文件列头在第1行
3. **空行清理**：数据末尾可能有空行，需 `dropna(how='all')` 清理
4. **数据类型**：序号和药品代码数量应转为整数，药品代码应保持字符串格式
5. **批次连续性**：药品限适应症规则跨多批次（第十二~十七批），导入时需合并去重
