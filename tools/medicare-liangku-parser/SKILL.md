# 医保智能监管规则知识点解析器

本 Skill 专门用于解析国家医保局发布的多批次医保智能监管"两库"（规则库 + 知识库）规则知识点明细 Excel 文件，以医保专家视角对药品和医疗服务项目相关规则进行分析、归纳、总结。解析结果需关联三目（药品/项目/耗材目录）形成可执行的有效规则，并向 `docs/RULE_REGISTRY.md` 规则注册中心注册规则编码。

## 适用场景

- 用户上传医保规则知识点明细 Excel 文件（文件名含"第X批""规则对应知识点明细"等关键词）
- 用户要求解析、归纳、总结医保监管规则
- 用户需要将规则知识点导入数据库或生成规则清单
- 用户需要以医保专家视角分析药品或医疗项目的限定规则

## 文件识别

### 文件命名规律

国家医保局发布的知识点明细文件遵循统一命名格式：

```
第X批-序号_"规则名称"规则对应知识点明细.xlsx
```

示例：
- `第三批-1 "药品限工伤保险"规则对应知识点明细.xlsx`
- `第八批-1 "医疗服务项目限定频次"规则对应知识点明细.xlsx`
- `第十二批 "药品限适应症"规则对应知识点明细.xlsx`

### 文件类型自动识别

根据 Sheet 名称和列结构，自动识别三种文件类型：

| 文件类型 | Sheet 特征 | 典型列 |
|----------|-----------|--------|
| **药品类规则** | 含"知识点明细"+"知识点对应药品代码"两个 Sheet | 序号、药品通用名、检出逻辑、逻辑依据、知识点对应药品代码数量 |
| **医疗服务项目类规则** | 仅含 1 个"知识点明细" Sheet | 序号、医疗服务项目名称、检出逻辑、逻辑依据、项目代码供参考 |
| **项目对类规则** | 仅含 1 个 Sheet（第七批重复收费专用） | 序号、时间区间、项目A名称、项目A代码、项目B名称、项目B代码、检出逻辑、逻辑依据 |
| **中药饮片类规则** | 仅含 1 个 Sheet | 序号、中药饮片名称、中药饮片代码、检出逻辑、逻辑依据 |

### 核心字段辨析：检出逻辑 vs 逻辑依据

Excel 中的"检出逻辑"和"逻辑依据"是两个容易混淆但性质完全不同的字段，导入数据库后分别映射为不同的列：

| 维度 | 检出逻辑 | 逻辑依据 |
|------|---------|---------|
| **本质** | HOW — 怎么检出违规 | WHY — 为什么算违规 |
| **粒度** | 同一批次/同一规则类型共用一条 | 每个知识点各不相同 |
| **内容** | 标准化的检测条件模板 | 具体的政策限制文本 |
| **数据库字段** | `action_message` | `source_reference` |
| **作用** | 生成提示消息 + 指导 conditions 结构 | 人工复核依据 + 政策溯源 |

三者在引擎中的分工：

```
Excel原始数据
├── 检出逻辑 → action_message    → 给医生看的提示消息
├── 逻辑依据 → source_reference → 给审核人员看的政策依据
└── (两者结合) → conditions      → 引擎实际执行的可计算规则
```

#### 示例：第九批"药品限二线使用"

以第九批为例，6 条知识点的"检出逻辑"完全相同，但"逻辑依据"各不相同：

| 药品通用名 | 检出逻辑（共用） | 逻辑依据（各不相同） |
|-----------|----------------|-------------------|
| 阿可替尼胶囊 | 使用了该药品，但没有一线药品使用无效或不能耐受的证据 | 限既往治疗后接受治疗的成人CLL/SLL患者 |
| 艾拉莫德片 | **同上** | 限活动性类风湿关节炎的二线治疗 |
| 艾普拉唑肠溶片 | **同上** | 限十二指肠溃疡和反流性食管炎患者的二线用药 |
| 艾曲泊帕乙醇胺片 | **同上** | 限ITP经皮质激素/免疫球蛋白治疗反应不佳者 |

**检出逻辑**整批完全一样，因为"二线用药限定"的检测模式是统一的。

**逻辑依据**每条都不同，因为每个药品的限制范围来自国家药品目录的不同备注。

#### 示例：第十二批"药品限适应症"导入数据库后的映射

| id | 药品 | action_message（检出逻辑） | source_reference（逻辑依据） | conditions（实际执行的DSL） |
|----|------|---------------------------|---------------------------|--------------------------|
| 792 | 阿加糖酶α | 使用药品的疾病诊断不符合限定支付适应症 | 限法布雷病患者的长期酶替代治疗 | `med_list_code in [XA16ABA...] AND diagnosis_codes not_contains [E75.2]` |
| 793 | 氟他胺 | **同上** | 限放化疗 | `med_list_code in [XA04ADA...] AND diagnosis_codes not_contains [Cxx]` |
| 794 | 雷洛昔芬 | **同上** | 限绝经后女性骨质疏松症 | `med_list_code in [XA11CCA...] AND diagnosis_codes not_contains [M81.0]` |

6 条规则的 `action_message` 全是同一句话，但 `source_reference` 和 `conditions` 各不相同。

#### 总结

- **检出逻辑**是"模板"，决定 `conditions` 的 DSL 结构（如"诊断不符合适应症" → `diagnosis_codes not_contains`）
- **逻辑依据**是"参数"，提供 `conditions` 中的具体取值（如"限法布雷病" → ICD-10 `E75.2`）
- **conditions** 是"编译后的可执行代码"，引擎只看这个字段执行

引擎执行 `conditions`，审计人员看 `source_reference`，医生收到 `action_message`。

### 数据行偏移

所有文件的前 3 行为标题/空行，**第 4 行（index=3）为实际列头**，第 5 行起为数据。解析时必须设置 `header=None` 读取后手动定位列头行。

### 解析注意事项

1. **统一用 str 读取**：所有列用 `dtype=str` 读取，避免项目代码（15位数字）被转为 float
2. **过滤非数据行**：数据末尾可能有"合计"行和"备注："开头的说明行，必须过滤
3. **重复文件去重**：同一批次+规则名称的文件只保留第一个（如第十批有两个完全相同的文件）
4. **子批次号取 Sheet 名**：文件名和 Sheet 名的子批次号可能矛盾（如第十一批），以 Sheet 名为准
5. **合并单元格处理**：药品代码 Sheet 中"对应知识点序号"列存在合并单元格，需 `ffill()` 前向填充
6. **药品代码数量校验**：解析后应验证"知识点对应药品代码数量"与实际关联到的代码数是否一致

### 步骤 1：扫描文件并自动分类

```python
import pandas as pd
import os, glob, re

def scan_and_classify(file_path):
    """扫描 Excel 文件，自动识别文件类型和规则批次"""
    xls = pd.ExcelFile(file_path)
    sheets = xls.sheet_names
    fname = os.path.basename(file_path)

    # 提取批次号
    batch_match = re.search(r'第([一二三四五六七八九十]+)批', fname)
    batch = batch_match.group(0) if batch_match else '未知批次'

    # 提取规则名称
    rule_match = re.search(r'"(.+?)"', fname)
    rule_name = rule_match.group(1) if rule_match else '未知规则'

    # 判断文件类型
    if '药品代码' in ' '.join(sheets):
        ftype = 'drug'
    elif '中药饮片' in fname or '中药饮片' in ' '.join(sheets):
        ftype = 'herbal'
    else:
        ftype = 'project'

    return {
        'file_path': file_path,
        'filename': fname,
        'batch': batch,
        'rule_name': rule_name,
        'file_type': ftype,
        'sheets': sheets
    }
```

### 步骤 2：解析知识点明细

```python
def parse_rule_knowledge_points(file_path, file_type='drug'):
    """解析知识点明细 Sheet，自动定位列头行"""
    xls = pd.ExcelFile(file_path)
    # 知识点明细通常在第一个 Sheet
    sheet_name = xls.sheet_names[0]

    # header=None 读取，手动定位列头
    raw = pd.read_excel(xls, sheet_name=sheet_name, header=None)

    # 查找列头行（包含"序号"的行）
    header_row = None
    for i in range(min(10, len(raw))):
        if raw.iloc[i, 0] == '序号':
            header_row = i
            break

    if header_row is None:
        header_row = 3  # 默认第4行

    df = pd.read_excel(xls, sheet_name=sheet_name, header=header_row)
    df = df.dropna(subset=[df.columns[0]])  # 去掉空行
    return df
```

### 步骤 3：解析药品代码（仅药品类文件）

```python
def parse_drug_codes(file_path):
    """解析知识点对应药品代码 Sheet"""
    xls = pd.ExcelFile(file_path)
    code_sheet = [s for s in xls.sheet_names if '药品代码' in s][0]

    raw = pd.read_excel(xls, sheet_name=code_sheet, header=None)
    header_row = None
    for i in range(min(10, len(raw))):
        if raw.iloc[i, 0] == '对应知识点序号':
            header_row = i
            break
    if header_row is None:
        header_row = 3

    df = pd.read_excel(xls, sheet_name=code_sheet, header=header_row)
    df = df.dropna(subset=[df.columns[0]], how='all')
    # 前向填充对应知识点序号（合并单元格导致的空值）
    df[df.columns[0]] = df[df.columns[0]].ffill()
    return df
```

### 步骤 4：以医保专家视角归纳规则

解析完成后，按以下维度归纳总结：

1. **规则分类**：将所有知识点按规则大类归类（药品/医疗服务项目/中药饮片）
2. **检出逻辑汇总**：提取每条规则的检出逻辑，归纳为标准化检测条件
3. **逻辑依据提取**：保留原始政策依据（药品目录备注/国家项目单位等）
4. **覆盖范围统计**：统计每批规则涉及的药品/项目数量
5. **规则清单输出**：生成结构化的规则清单表

### 步骤 5：二次复查纠偏（verify_and_fix）

解析完成后自动执行二次复查，检查以下 10 类问题：

| 检查项 | 检查内容 | 处理方式 |
|--------|---------|---------|
| 1. 必填字段缺失 | 药品名/检出逻辑/逻辑依据是否为空 | 报告需人工确认 |
| 2. 药品代码数量不一致 | 声明数量 vs 实际关联代码数 | 有代码时自动修正，无代码时报告 |
| 3. 药品代码格式异常 | 是否以 X/Z/T 开头 | 报告需人工确认 |
| 4. 项目代码变 float | 是否含 e+ 科学计数法或 .0 后缀 | 报告需人工确认 |
| 5. 项目对名称为空 | 项目A/B名称是否缺失 | 报告需人工确认 |
| 6. 项目类代码 float | 同检查4，针对项目类文件 | 报告需人工确认 |
| 7. 检出逻辑为空 | 项目/中药饮片类检出逻辑是否缺失 | 报告需人工确认 |
| 8. 序号重复 | 相邻知识点序号是否重复 | 报告需人工确认 |
| 9. 非数据行残留 | 是否有"备注"/"合计"等行残留 | 报告需人工确认 |
| 10. 序号连续性 | 序号是否从1连续递增 | 报告缺失序号 |

复查报告输出格式：
```
================================================================================
二次复查纠偏报告
================================================================================
  总计发现 X 个问题
  自动修复: Y 个
  需人工确认: Z 个

--- 问题明细 ---
  [批次 规则名称] N 个问题:
    第X条: 问题描述
```

### 步骤 6：人工确认后独立复查（--reverify）

人工确认并修正问题后，**必须再跑一次复查**，确认：
1. 修复是否生效 — 原来报的问题已消除
2. 是否引入新问题 — 手工修改没有意外破坏其他数据

支持三种命令行模式，形成 **"解析 → 自检 → 人工确认 → 再自检"** 完整闭环：

```bash
# 模式1：解析 Excel + 自动复查（首次解析）
python parse_rules.py <excel目录>

# 模式2：解析 Excel + 自动复查 + 保存 JSON（首次解析，导出供修正）
python parse_rules.py <excel目录> --save <输出JSON路径>

# 模式3：仅复查（从已修正的 JSON 加载，不重新解析 Excel）
python parse_rules.py --reverify <JSON路径>
```

**典型工作流**：
1. 首次解析：`python parse_rules.py /path/to/excels --save /tmp/rules.json`
2. 查看复查报告，人工修正 JSON 中的问题数据
3. 独立复查：`python parse_rules.py --reverify /tmp/rules.json`
4. 若仍有问题，重复步骤 2-3，直到复查报告显示 **"所有数据校验通过，可安全导入数据库"**

## 数据库导入

解析后的规则数据可导入数据库的以下表：

| 目标表 | 用途 | 关键字段 |
|--------|------|---------|
| `rule_items` | 规则主表 | rule_code, rule_name, rule_category, conditions, action |
| `YP` | 药品目录 | code, name, restricted_indication, restricted_insurance |
| `FW` | 诊疗项目目录 | med_list_codg, med_list_name, billing_unit, chrgitm_lv |
| `consumables` | 耗材目录 | code, name |

导入时 `rule_items.conditions` 字段使用 JSON DSL：
```json
{
  "logic": "AND",
  "conditions": [
    {"field": "claim_line.med_list_code", "op": "in", "value": ["XL01ELA387E001010184513"]},
    {"field": "claim_event.insurance_type", "op": "!=", "value": "工伤"}
  ]
}
```

DSL 支持 17 种运算符、9 组字段别名、48 个引擎字段（含 17 个计算字段）。完整运算符和字段参考见 `references/rulebook.md` 第六章。

## 注意事项

1. **合并单元格处理**：药品代码 Sheet 中"对应知识点序号"和"药品通用名"列存在合并单元格，需前向填充（`ffill`）
2. **列头行不固定**：不同批次文件的列头行可能在第 3 或第 4 行，需动态检测
3. **编码格式**：药品代码格式为 `X` 开头（西药）/`Z` 开头（中成药）/`T` 开头（中药饮片）
4. **项目代码格式**：国家医保局全国医疗服务项目代码为 15 位数字
5. **逻辑依据来源**：药品类引用"国家药品目录备注"，项目类引用"国家医保局全国医疗服务项目"
